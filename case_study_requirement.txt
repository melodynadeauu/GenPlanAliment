Dans le cadre du processus d’entrevue, voici une mise en situation visant à évaluer vos capacités techniques en lien avec le poste. 

Contexte
Vous intervenez comme consultant(e) auprès d'un client fictif, une entreprise de mieux-être qui souhaite offrir à ses employés un assistant IA de planification alimentaire. Le client demande un prototype fonctionnel accompagné d'une conception défendable, qui sera présenté comme lors d'une entrevue client.



Sources de données persistantes (à créer vous-même)
    •    Base de données SQLite (meal_prep.db) : contient un calendrier hebdomadaire d'activités sportives (table activity_calendar : jour, activité, durée en minutes, intensité).
    •    Fichier JSON (food_preferences.json) : liste des aliments préférés (likes) et non préférés (dislikes).
    •    API USDA FoodData Central : fournit les informations nutritionnelles. Vous devez construire une application qui sera connectée à cette API (https://fdc.nal.usda.gov/api-guide). 
    ◦    Une clé API gratuite est requise. 
    ◦    Limite de 1 000 requêtes/heure → à prendre en compte dans la solution développée.

    •    


Objectif principal
Concevoir une application avec un agent IA capable de générer un plan alimentaire quotidien optimisé selon le profil suivant :
    •    Âge : 45 ans
    •    Poids : 220 lb (100kg)
    •    Grandeur : 6 pi 5 po (196 cm)
    •    Objectif : perte de poids
La solution doit être développée en code (une approche exclusivement low-code ou no-code n'est pas attendue dans le cadre de cet exercice). Lors de la deuxième partie de l'entrevue, vous devrez expliquer les principaux éléments de votre implémentation et apporter certaines modifications au code en direct. Un schéma d'architecture présentant les composantes de la solution, leurs interactions et les flux de données devra également être fourni. Vous êtes libre de choisir les technologies, outils, plateformes et modèles d'IA de votre choix. Il n'est pas nécessaire d'utiliser les technologies Microsoft pour réaliser cette solution.



Fonctionnalités attendues
Interface utilisateur
    •    Interface simple et intuitive facilitant l'utilisation.
Paramétrage
    •    Possibilité de modifier : âge, poids, grandeur, objectif et préférences alimentaires.
Orchestration multi-sources
    •    Prendre en compte :
    ◦    Activité sportive du jour (SQLite)
    ◦    Préférences alimentaires (JSON)
    ◦    Données nutritionnelles réelles (API USDA)
Contrainte technologique
    •    La génération du plan alimentaire doit être réalisée par un agent IA utilisant un modèle de langage (LLM). Une approche basée uniquement sur des règles métier ou des recommandations déterministes n'est pas suffisante.
Garde-fous
    •    Intégrer des mécanismes de sécurité liés aux données de santé et à l'objectif de perte de poids.
    •    Identifier et justifier les risques.
Robustesse
    •    Gestion des erreurs API
    •    Gestion des aliments introuvables
    •    Validation des entrées utilisateur

Déroulement de l'entrevue
    •    ~10 minutes : présentation de la solution (démo + schéma d’architecture) faite comme devant un client, avec mise en avant de la valeur apportée par votre solution.
    •    ~25 minutes : questions techniques, discussion architecturale et modifications de code en lien avec la solution développée.
    •    ~10 minutes : questions sur l’écosystème Microsoft (Copilot, Power Platform, Azure) — les questions sont indépendantes de la solution à développer et vous ne devez pas vous limiter à l’écosystème Azure pour le développement de la solution.
